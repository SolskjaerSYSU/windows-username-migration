## ⚠️ 这是不是你的痛？

中文 Windows 用户名的路径 `C:\Users\中文用户名` 会让一堆工具莫名炸裂：

- Node/pnpm/pip/conda 缓存路径报错、编译器编码错乱
- **AI Agent / CLI 工具**（Codex、Claude、各类沙箱服务）在非 ASCII 路径下行为异常
- 某些安装器直接拒绝安装，或者装完就找不到自己的目录

⚠️ **改显示名没用**（控制面板里改的只是显示名，路径纹丝不动）。
**唯一正解**是把配置文件夹真正改名——但这事深水区极多，本仓库就是那张藏宝图。

## 🧭 铁律（先记住再往下看）

| 铁律 | 为什么 |
|---|---|
| **只做原位重命名，永不复制/移动/删除** | 同分区改名是纯元数据操作，瞬间完成，从根源排除"复制中断丢文件" |
| **预检不过，立即中止** | 每次失败都必须"当作没发生过"——本仓库作者连续失败 5 次，0 损失 |
| **一切写日志，失败自动取证** | 看不见的占用者，要让日志替你点名 |
| **动手前必须有** | 完整备份（放另一块盘）+ 注册表导出 + 系统还原点 + 恢复管理员账户 |

## 💣 六个真实的坑（前 5 次失败的完整尸检）

| # | 表面现象 | 真实根因 | 解法 |
|---|---|---|---|
| 1 | 注册表文件"被另一进程使用" | "切换用户"≠注销，旧会话 hive 还挂着 | hive 锁探针 + 要求真正重启；无会话残留可强制卸载 |
| 2 | 改名"访问被拒绝" | 十几个计划任务以旧身份运行，登录瞬间抢跑占句柄 | 按运行身份枚举禁用 + 清进程 |
| 3 | "在登录界面等了 3 分钟"却毫无变化 | **ARSO 自动重启登录**：系统根本没停在登录界面 | 策略级关闭 `DisableAutomaticRestartSignOn` |
| 4 | 过滤了任务却一个没匹配到 | 任务的 Principal 存**账户名**而非 SID（也可能反之） | 名字 + SID 双条件匹配 |
| 5 | 万事俱备仍被拒 30 秒 | 一个**自启动服务**握着文件夹根目录的句柄（本例：某 AI 工具的沙箱服务） | **handle64 句柄取证点名 + 动态清除器** |
| 6 | 用户在迁移中登录报"密码错误"（极度惊恐） | 登录撞上"账户改名"的最后几秒 | 迁移末段阻止登录/提前告知；事后用日志时间线安抚 |

每个坑的完整"症状 → 根因 → 解法 → 代码要点"见 **[SKILL.md](SKILL.md)**。

## 🚀 使用方法

> 适合人群：本地账户（微软账户亦可）、愿意花 30 分钟、能接受"先备份再动手"的人。
> 不适合：懒于备份、期望 5 分钟搞定、企业域环境（另有策略冲突）。

```
1. 通读 SKILL.md 的铁律与六坑，按 §1 勘察你的机器
2. 备份：用户数据 → 另一块盘；注册表 .reg 导出；建系统还原点；建恢复管理员
3. 关闭 ARSO（step2d）—— 否则你"等登录界面"的一切努力都是幻觉
4. 跑迁移脚本（推荐开机任务方式 step2b，可续跑、幂等、成功自删）
5. 重启 → 在真正的登录界面等 2 分钟 → 登录 → step3 验证 10/10
6. 一切正常一周后：删除恢复账户、删除备份
```

| 脚本 | 作用 |
|---|---|
| `scripts/scan_config.ps1` | 扫描配置文件中的旧路径硬编码 |
| `scripts/step1_prepare_admin.ps1` | 恢复管理员 + 系统还原点 |
| `scripts/step2d_disable_arso.ps1` | 关闭 ARSO（必做！） |
| `scripts/step2b_boot_rename.ps1` | ⭐ 开机迁移主脚本（动态清除器、可续跑、成功自删） |
| `scripts/step2_rename_profile.ps1` | 交互式迁移（备用方案） |
| `scripts/step3_verify.ps1` | 迁移后 10 项验证 |
| `scripts/clean_residual.ps1` | 残留路径清理（大小写/正斜杠/转义/编码全变体） |

**使用前必改**：脚本顶部的 `$newName`（新用户名）、SID 占位符、工作目录路径。

## 🔬 这个仓库的独家价值

1. **纯重命名哲学**：网上多数教程让你"新建账户再拷数据"——那是数据丢失的温床。
   本手册的方案从不触碰文件内容，回滚 = 把名字改回去。
2. **存储形式 ≠ 显示形式**：计划任务的 Principal 可能存名字也可能存 SID；
   路径残留有大小写/正斜杠/双反斜杠/TOML 转义/GBK 编码等全部变体——
   每一个变体都是一个"神秘 FAIL"，本手册列全了。
3. **句柄取证方法论**：当所有常规手段都排除后仍失败，用 [Sysinternals Handle](https://learn.microsoft.com/sysinternals/downloads/handle)
   点名隐形占用者，再用"动态清除器"（扫描→停服务→杀进程→重试前重扫）自愈。
4. **Agent 时代的元经验**：如何给 AI 助手布置这类高危任务（预检中止、自动取证、
   双击按钮、UAC 预告、日志时间线安抚）——见 SKILL.md §7。
